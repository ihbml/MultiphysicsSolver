§1 · dataflow

Nine modules, one dependency DAG,
zero virtual calls in the hot loop

Dispatch happens once per physics, per time step — through a procedure pointer table, not a class-bound type. Inside the quadrature loop everything is concrete, contiguous and inlined.

memory contract

Structure of arrays, padded, unit-stride

! ✗ array of structures — strided, unvectorisable
type(node_t) :: nodes(nnodes)
! ✓ SoA — one 64B line = 8 doubles, unit stride
real(wp), allocatable, aligned(64) :: x(:), y(:), z(:)
integer(lidx), allocatable, aligned(64) :: c2n(nnpe,ncells)
  • ▸ element table stored nnpe-major → the 3/4/8 nodes of one cell sit in 64 B
  • ▸ stride padded to mod(nnpe,4)=0 rows so no lane crosses a page
  • ▸ fields live in one slab → GPU transfers are present(), never copyin
  • ▸ halo ghost region appended, so assembly is branch-free over owned+ghost

§4 · performance doctrine

Fast because it refuses to be clever in the wrong places

roofline-aware · memory-bound ops get fused, compute-bound ops get BLAS-3
01 · bandwidth

One pass per element, forever

Stiffness assembly, quadrature, constitutive update and the residual all run in a single fused sweep (matrix-free FET-DP style). When a Krylov solve needs a global matrix we build it once as CSR and keep it in a blocked 32×32 hybrid for the SpMV. Arithmetic intensity climbs from 0.3 to ~6 flop/B.

02 · parallelism

Colour first, then atomic-free

Cells are grey-coloured on the shared-node graph, so !$omp parallel do writes are conflict-free without atomics; GPU offload uses collapse(2) over (cell, quad point) with warp-aggregated atomics only for the last colour. RCM + nested dissection (Rust) cuts fill-in before the factorisation ever sees the matrix.

03 · accuracy

Determinism is a feature

Global reductions use blocked pairwise + Kahan compensation in real128 when available, bit-reproducible across thread counts. -ffast-math is off; only -fno-math-errno and -fprotect-parens. FPE traps active in debug: NaN propagates to the report, not into a silent divergence.

§5 · verification & VV&U gate

Every physics kernel ships with
a manufactured solution and an order assertion

The CI matrix runs the MMS suite at 4 refinement levels on 1…64 ranks and on GPU. A build fails if measured_order < p_expected − 0.05, if the Krylov solve stops early, or if the discrete energy balance drifts more than 1e-10 relative.

  • ✓Gauss–Lobatto mass lumping is opt-in and reported in the header of every run, so a lumped result can never masquerade as a consistent-mass result.
  • ✓Time integrator is order-adaptive; the PI controller is fed the true local error estimator, so order drops are earned, not guessed.
  • ✓Coupling residual is measured on the transmission condition, not the algebraic residual — a relaxed Picard can look converged and be wrong.
  • ✓Checkpoint = access='stream' self-describing header + CRC of the field slab; restart is bit-identical for steady and BDF-continuous for transient.

      -DMPHE_ARCH=native -DMPHE_OPENACC=on -DMPHE_MPI=on

ctest --test-dir build -R mms --output-on-failure      # the accuracy gate

      --mesh-inline --max-h 4e-3 --rtol 1e-8 --acc-dev gpu:0
