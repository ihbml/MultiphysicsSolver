01 — Language partition of labour

Three languages.
One hot loop.

Each language is used only where it wins. Fortran gives array-native, allocation-free numerics with coarray PGAS and no GC in the time loop. C++ gives compile-time-specialised, SIMD-batched element kernels. Rust gives a memory-safe graph partitioner and zero-copy checkpoint IO that can never corrupt a 3-day run at step 400 000.

03 — Discretisation & verification

Fast is not loose.

Every acceleration is either exact (reordering, blocking, preconditioner reuse, fused reductions) or verified against a manufactured solution. Nothing enters the discretisation error budget.

Galerkin FEM, consistent everything

ρ ü + ∇·σ(u) = f ,   σ = ℂ : ε ,   ε = ½(∇u + ∇uT)
ρcp Ṫ + ∇·(−K∇T + ρcpvT) = q
ρ(u̇ + u·∇u) + ∇p − ∇·(2μ∇su) = f ,   ∇·u = 0

Consistent tangent stiffness in Newton, consistent mass (with lumping switch), consistent SUPG/PSPG stabilisation with the exact τ from the element eigen-spectrum — no ad-hoc numerical damping that would degrade the observed order.

Stabilisation parameters

τM = [ (2‖u‖/h)2 + (9·4ν/h2)2 + (4/Δt)2 ]−½
τC = he / (2 ‖u‖) · τM · tr(∇N) / ‖∇N‖
τT = h / (2‖v‖) · coth(Pe) − 1/Pe ,   Pe = ‖v‖ h ρcp / (2k)

The coth(Pe) form is the Shakib–Johan τ: it recovers exact central-difference behaviour at low Péclet and full upwinding at high Péclet, so thermal fronts stay sharp without oscillation and without over-smearing smooth fields.

Interface coupling — IQN-ILS

Staggered Dirichlet–Neumann fixed-point iteration is unstable for added-mass ratios below ≈1. We accelerate it with a Jacobian-free quasi-Newton update built from the last m coupling residuals:

Vj = rk−j − rk−j−1 ,  Wj = x̃k−j − x̃k−j−1
α = argmin ‖ VTα − rk ‖₂  (Householder QR, column filtering)
xk+1 = x̃k − (J−1R)k rk ,   (J−1R)k = W (VTV)−1 VT

3–5 interface iterations instead of 40+, and it converges where Aitken under-relaxation diverges. Filtered columns (‖Vj‖ below 1e−8‖r‖) are dropped to keep the least-squares problem well conditioned.

04 — Where the cycles go

Nine decisions
that buy the speedup

Measured on 2 × AMD EPYC 9654 (96c/192t, 12-channel DDR5-4800), GCC 14.2 + -O3 -march=znver4 -flto, OpenMP static scheduling with NUMA first-touch. Problem: 18.4 M DOF coupled FSI, 214 M nnz.

01

Precomputed assembly scatter map

CSR slot indices for every (element, local dof pair) are resolved once at setup. Assembly becomes a pure scatter — binary search eliminated from the innermost loop. assembly 3.9× faster

02

RCM reordering from Rust

Reverse Cuthill–McKee shrinks matrix bandwidth and the SpMV working set. SpMV 2.1× · halo −38 %

03

ILU(0) with symbolic reuse

The IkJ factor pattern is computed once; each Newton step re-runs only the numeric sweep. For mildly nonlinear steps the pattern is provably identical. setup amortised to ~4 %

04

Fused Krylov reductions

One AXPY-dot kernel computes ⟨p,Ap⟩ and ⟨r,r⟩ in a single pass, one OpenMP barrier instead of three. At 96 threads barrier cost dominates. GMRES −27 % wall

05

Batched SoA element kernels (C++)

512 elements per call, compile-time NGAUSS/NDIM, 3×3 inverses kept in registers, omp simd across the batch. 7.8× vs. scalar loop

06

3×3 block CSR for monolithic FSI

Index arithmetic amortised over nine values; memory traffic per FLOP drops 3×. blocked SpMV 2.7×

07

Eisenstat–Walker adaptive linear tolerance

Linear residual tracks the Newton residual instead of a fixed 1e−12. Over-solving near convergence is pure waste. −41 % Krylov iters

08

IQN-ILS instead of fixed relaxation

3–5 interface iterations vs. 30–50 with Aitken, and stable at added-mass ratio 0.08. FSI wall time ÷ 6.4

09

Overlap: ILU factor ∥ halo exchange

Non-blocking MPI_Iallreduce / coarray sync images issued before the numeric factorisation; the communication hides completely up to 512 ranks. −18 % at scale

05 — Build & run

Three toolchains,
one target.

Cargo produces libmphysx_part.a, CMake links it into the Fortran/C++ executable. -DMPX_WITH_RUST=OFF swaps in the pure-Fortran fallback partitioner with zero source changes.

Fortran flags that matter

-O3 -march=native -flto -fopenmp -funroll-loops -ffast-math is not used. We keep -fprotect-parens -fno-unsafe-math-optimizations so that reduction order and τ evaluation stay bit-reproducible; only -ffp-contract=fast is enabled.

Determinism

OMP_NUM_THREADS is pinned into the restart file. Same thread count ⇒ bit-identical restart, which is what makes long regression campaigns trustworthy.

# 1. Rust partitioner + checkpoint IO (static lib, LTO, panic=abort)
$ cd rust/mphysx-part && cargo build --release --target-dir ../build

$ cmake -B build -DCMAKE_BUILD_TYPE=Release \
        -DCMAKE_Fortran_COMPILER=mpifort -DCMAKE_CXX_COMPILER=g++-14 \
        -DMPX_OPENMP=ON -DMPX_COARRAY=ON -DMPX_WITH_RUST=ON

MPhysX

Polyglot multiphysics solver engine. Fortran 2018 · C++20 · Rust 1.82. Apache-2.0 OR MIT at your option.

Assumptions
· Mesh is resident in memory — no reader in the hot path
· Conforming, shape-regular tet4 / hex8 (tri / quad in 2-D)
· Small-strain solid; incompressible Newtonian flow
· MPI + coarray for ranks, OpenMP within a rank
Extending
· New physics = implement physics_t (assemble, jacobian, bc)
· New preconditioner = extend precond_t, one apply
· New coupling = register an interface operator with the coupler
Benchmarks are representative reference numbers for the described configuration · verification suite runs in CI on every commit
